# 国标消防终端（大华 v1.03）接入

平台内置解析器 `gb26875_dahua_parser@1.0.0`，处理完整的 GB/T 26875.3-2011 TCP/UDP 二进制帧。当前接入范围包括注册、保活、确认、时钟同步请求/应答以及设备最常用的部件状态上报：手动火灾报警按钮、感烟/感温探测器和声光报警器。解析器校验 `@@`/`##`、应用数据长度（最大 512 字节）和控制单元加应用数据的 8 位累加校验和。

## 平台原始消息封装

接入服务监听终端 TCP 连接，校验完整帧后将其以 Hex 字符串放入平台原始消息 `payload`，并按协议向终端返回确认帧。协议包配置如下：

```json
{
  "protocol": "gb26875-dahua-v1.03",
  "transport": "TCP_UDP_BRIDGE",
  "payloadFormat": "hex",
  "parserType": "gb26875_dahua_parser"
}
```

解析结果包含 `fireAlarm`、`fault`、`componentType`、`componentTypeName`、`circuitAddress`、`nodeAddress`、`statusWord` 和完整 `objects`。火警或故障状态会生成 `ALARM_REPORT`，正常状态变化生成 `STATE_CHANGE`。

启动 TCP 接入服务：

```powershell
docker compose --profile gb26875 up -d --build gb26875-gateway
```

真实终端把平台地址配置为 Docker 主机 IP、端口 `26875`（TCP 或 UDP）。接入服务会按帧中 6 字节源地址自动创建 `gb26875_<源地址>` 设备，保留完整原始帧，并在平台成功接收后返回 `0x03` 确认帧。UDP 按单个数据报承载一个完整协议帧处理；现场仍需核对设备端的超时和三次重发参数。

## 一问一答时序

协议 v1.03 的通信不是单向上报：控制命令使用“发送/确认”，参数设置和信息查询使用“请求/应答”，信息上报则由终端主动发送、平台确认。当前网关的行为为：

- 注册、保活、系统/部件状态和模拟量上报：校验并成功归档后，平台立即返回同业务流水号、目的地址为设备地址的 `0x03` 确认帧；归档失败不回确认，让设备按协议重发。
- 终端发送命令 `0x01`、类型标志 `0x5A` 的时钟同步请求：平台返回 `0x01` 时钟同步帧（8 字节应用数据，6 字节 BCD 时间），不会额外再回 ACK。
- 终端确认平台时钟同步的 `0x03` 帧：平台完成本次请求，不会对 ACK 再发送 ACK。

虚拟设备可以直接验证这条请求/应答链路：

```powershell
go run ./cmd/gb26875-virtual-device --gateway localhost:26875 --scenario time-sync-request
```

参数设置和信息查询仍需按设备能力增加对应命令构造器；当前代码已经把连接管理、时钟同步请求应答和重发所需的确认边界分开，不能把“收到原始报文”当作协议完成。

网关也提供可选的本地控制接口用于平台主动校时。默认不启动；启用时务必绑定本机并设置令牌：

```powershell
$env:GB26875_CONTROL_LISTEN = '127.0.0.1:26876'
$env:GB26875_CONTROL_TOKEN = 'change-this-control-token'
go run ./cmd/gb26875-gateway

Invoke-RestMethod -Method Post http://127.0.0.1:26876/api/v1/devices/gb26875_123456789012/time-sync `
  -Headers @{ 'X-Gateway-Token' = $env:GB26875_CONTROL_TOKEN }
```

接口只有在设备保持 TCP/UDP 会话时才会发送请求，并等待同业务流水号的设备确认；超时返回 504。Docker Compose 已预留 `GB26875_CONTROL_LISTEN`、`GB26875_CONTROL_TOKEN` 和本机 `26876` 端口映射，不能把控制端口直接暴露到公网。

## 虚拟设备

平台启动后执行：

```powershell
go run ./cmd/gb26875-virtual-device --scenario manual-alarm
```

命令会幂等创建并发布协议包、产品和虚拟设备，然后上报一帧手报火警。可用场景：

- `manual-alarm` / `manual-normal`
- `smoke-alarm`
- `sound-light-start` / `sound-light-stop`

通过真实 TCP 接入链路测试（先启动 `gb26875-gateway`）：

```powershell
go run ./cmd/gb26875-virtual-device --gateway localhost:26875 --scenario manual-alarm
```

UDP 链路：

```powershell
go run ./cmd/gb26875-virtual-device --gateway localhost:26875 --network udp --scenario sound-light-start
```

只生成协议帧、不访问平台：

```powershell
go run ./cmd/gb26875-virtual-device --scenario sound-light-start --dry-run
```

平台地址、租户和测试账号可以通过 `--platform`、`--tenant`、`--username`、`--password` 修改。账号参数仅用于本地测试初始化，不应在生产脚本中保存管理员密码。
